# ADR-0004: MAIN worldの通信ラッパは既定OFFの補助層とする

- ステータス：採用
- 日付：2026-09-20
- 関連：開発ドキュメント 4.5, 5.10、ADR-0003

## コンテキスト

ADR-0003のUIイベント捕捉は、サイトの画面改修で漏れうる。漏れた場合、利用者は「守られているつもり」で個人情報を送信してしまう。最終防御として、ページが実際に送り出すリクエスト本文を検査したい。

これを行うには MAIN world（ページと同じ実行コンテキスト）で `window.fetch` などをラップする必要があるが、MAIN worldのコードはページ側から改変できるうえ、サイトの通常動作を壊すリスクがある。

## 決定

MAIN worldに注入する通信ラッパ `net-guard.js` を**任意機能**として実装し、**既定はOFF**とする。有効化は設定または管理者ポリシーで行い、`chrome.scripting.registerContentScripts` で登録する。

- ラップ対象：`window.fetch` / `XMLHttpRequest.prototype.send` / `WebSocket.prototype.send`
- 検出時は例外を投げて送信を失敗させ、`postMessage` でコンテンツスクリプトに通知してモーダルを表示する
- 受信側は `event.source === window`・`event.origin`・`source: 'pii-guard'` を検証し、**通知表示以外の処理は行わない**
- この層は**補助**であり、主防御はISOLATED worldのイベント捕捉であるという位置づけを変えない

## 理由

- **既定OFF**：この層は「サイトの通常動作を壊す」という、防御そのものより大きな業務影響を持ちうる。全社に配る初期値としては不適切
- **補助の位置づけ**：ページから上書き可能である以上、これを前提にした防御設計は成立しない。UIイベント捕捉の漏れを**検知して気づく**ための保険と見る
- **例外を投げて失敗させる**：通信を静かに握り潰すとサイトがハングしたように見える。失敗として返し、理由はモーダルで示す
- `postMessage` の受信を通知表示に限定するのは、ページ側から拡張機能の機能を呼び出させないため（6.4）

## 代替案

| 案 | 却下理由 |
| --- | --- |
| 既定ONで配布する | 対象サイトごとに本文形式（JSON、ストリーム、multipart）が異なり、誤ったラップがチャット自体を壊す。業務停止リスクを初期値で負うべきではない |
| 実装しない | UI捕捉漏れに気づく手段がなくなる。サイト改修が最大の運用リスクである以上（8.3）、有効化できる状態にはしておく |
| ISOLATED worldでラップする | ISOLATED worldの `fetch` を差し替えても、ページ側の `fetch` は別オブジェクトのため効果がない |
| `webRequest` で本文を見る | ADR-0003の代替案と同じ理由で不採用 |

## 結果

**得られるもの**

- サイト改修でUI捕捉が外れた場合でも、最後の地点で止まる可能性が残る
- 検証環境で有効化すれば、捕捉漏れの発見手段として使える

**引き受けるもの**

- ADR-0002のビルドチェックで、このファイルだけは `fetch` 等の参照を許可リストに入れる必要がある。許可リストに入るファイルは**個別レビュー必須**とする
- 有効化時はサイト別チェックリストに「通常動作が壊れない」検証項目が増える（7.3）
- ページ側から無効化されうるため、この層が動作していることを保証できない。**無効化の検知はできない**ことを運用に明示する
