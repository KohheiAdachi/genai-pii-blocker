# ADR-0008: 保存先を `storage.local` と `storage.managed` に限定し、検出値を保存しない

- ステータス：採用
- 日付：2026-09-20
- 関連：開発ドキュメント 5.9, 6.3、ADR-0002

## コンテキスト

拡張機能が扱うデータには、利用者設定、管理者ポリシー、検出ログ、そして検査対象の入力テキストそのものがある。このうち入力テキストと検出値は、まさに守ろうとしている個人情報である。

`chrome.storage.sync` は書くだけでGoogleアカウント経由でクラウドに同期される。通信コードを1行も書いていなくても、**ブラウザが外部へ送る**。ADR-0002の通信ゼロは、APIを使わないだけでは達成できない。

また、組織配布では管理者が設定を固定し、利用者が緩められないようにする必要がある（F-09）。

## 決定

| データ | 保存先 | 内容 | 保持期間 |
| --- | --- | --- | --- |
| 入力テキスト | **保存しない**（メモリ上で検査後に破棄） | ― | ― |
| 検出値 | **保存しない**（UIには `06******` のように伏せ字で表示） | ― | ― |
| 検出ログ | `storage.local` | 日付×サイト×種別×判定レベルの**件数のみ** | 90日 |
| 利用者設定 | `storage.local` | ルールON/OFF、カスタムルール | 無期限 |
| 管理者ポリシー | `storage.managed`（読み取り専用） | `schema.json` に沿った値 | OSのポリシー設定に従う |

- **`chrome.storage.sync` は使用しない**
- **`console.log` への入力テキスト・検出値の出力を禁止**する。開発時のデバッグ出力はビルドで除去する
- 設定の優先順位：`lockSettings: true` のとき管理者ポリシーのみを採用、それ以外は利用者設定に管理者ポリシーを上書き適用する
- コンテンツスクリプトからService Workerへ渡すのは**件数と種別のみ**で、検出値そのものは渡さない

## 理由

- **sync禁止**：通信ゼロを守るには、自分が呼ぶAPIだけでなく**ブラウザが代わりに送る経路**も塞ぐ必要がある。設定値に利用者のカスタムルール（業務固有の語を含みうる）が入ることも考えると、同期は明確に不適切
- **件数のみのログ**：F-10（件数の確認）と6.3（検出値を保存しない）を両立させる。`日付|サイト|種別|レベル` をキーにしたカウンタなら、個人情報を持たずに傾向を把握できる
- **90日で削除**：無期限に貯めても運用上の用途がなく、量だけが増える。書き込みのたびに古いキーを削除する方式なら、削除処理のための常駐が不要になる（MV3のService Workerは常駐しない）
- **managed storage を設定配信路とする**：通信せずに管理者の意図を端末へ届けられる唯一の経路であり、配信はブラウザ本体が行う（ADR-0002）
- **console出力の禁止**：DevToolsのログは他の拡張機能やページのスクリプトから読める場合があり、保存しない方針の抜け道になる

## 代替案

| 案 | 却下理由 |
| --- | --- |
| `storage.sync` で設定を端末間同期 | クラウド同期が発生し、通信ゼロの前提が崩れる |
| 検出値を含む詳細ログを残す | 誤検知の調査はしやすくなるが、個人情報のコピーを端末に作ることになる。守る対象を増やしてしまう |
| ログを無期限保持 | 用途がないまま `storage.local` が膨らむ。削除の契機も作りにくい |
| 設定を `manifest.json` の固定値のみにする | 組織ごとのルール調整ができず、緊急のルール変更手段が再配布だけになる |
| IndexedDB に構造化ログを持つ | 保存するデータが件数のみである以上、過剰。実装と削除処理が複雑になる |

## 結果

**得られるもの**

- 拡張機能が端末に残すデータが「件数」と「設定」だけになり、漏えい時の影響が限定される
- 管理者が設定を固定でき、利用者による無効化を防げる

**引き受けるもの**

- 誤検知の調査に**検出値を使えない**。利用者からの報告は「サイト・種別・日時」で受け、再現は評価コーパス側で行う（8.3）
- 設定が端末間で同期されないため、利用者が複数端末を使う場合は各端末で設定するか、管理者ポリシーで統一する
- `storage.managed` はポリシー未配布の環境では空になるため、取得失敗を前提にしたフォールバックが必要（`.catch(() => ({}))`）
