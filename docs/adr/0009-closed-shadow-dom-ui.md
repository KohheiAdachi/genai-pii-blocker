# ADR-0009: ブロックUIをclosed Shadow DOMに描画する

- ステータス：採用
- 日付：2026-09-20
- 関連：開発ドキュメント 5.7, 6.4

## コンテキスト

ブロックモーダルはAIサイトのページ内に描画される。ここには2つの異なる問題がある。

1. **見た目**：サイトのCSSがモーダルに適用され、レイアウトが崩れる。逆にモーダルのCSSがサイト側に漏れる
2. **信頼性**：モーダルは「このまま送信する」という、防御を解除するボタンを持つ。ページのスクリプトからこのボタンを参照して `click()` できるなら、検査は迂回できる

2番目は単なる見栄えの問題ではなく、ADR-0003で確保した防御位置を無効化しうる。

## 決定

モーダルは `attachShadow({ mode: 'closed' })` で作成したShadow DOM内に描画する。

- 検出値は `Detector.preview()` で伏せ字にしてから表示し、**完全な値をDOMに書き出さない**
- ボタンのハンドラでは `event.isTrusted` を検証し、スクリプトによる合成クリックを拒否する
- キーボード操作（Tab移動、Escで閉じる）と**フォーカストラップ**に対応する

## 理由

- **closed モード**では `element.shadowRoot` が `null` を返すため、ページのスクリプトから内部のDOMを辿れない。openモードでは要素を取得して `click()` できてしまう
- **`isTrusted` の検証**は、closed Shadow DOMを何らかの方法で突破された場合の二重の防御になる。合成イベントは `isTrusted === false` になるため、利用者の実際の操作だけを受け付けられる
- **伏せ字表示**は、ADR-0008の「検出値を保存しない」と対になる。DOMに完全な値を書けば、ページのスクリプトやスクリーンショットから読み取れる状態を自分で作ってしまう
- **Shadow DOMによるCSS隔離**で、サイト側のスタイル改修に影響されずモーダルの表示を保てる。サイトごとのCSS調整という保守作業が発生しない
- **フォーカストラップ**は、モーダル表示中に背後の入力欄へフォーカスが戻り、Enterで送信されることを防ぐ

## 代替案

| 案 | 却下理由 |
| --- | --- |
| 通常のDOM（`div` + 高いz-index） | サイトのCSSと衝突する。ページのスクリプトからボタンを直接操作できる |
| `mode: 'open'` のShadow DOM | `shadowRoot` 経由で内部を辿れるため、防御解除ボタンを押させられる |
| `iframe` にモーダルを描画 | 隔離は強いが、拡張機能ページのiframeを対象サイトに埋め込むと `web_accessible_resources` の公開が必要になり、攻撃面が増える。高さ調整やフォーカス制御も煩雑 |
| `window.alert` / `confirm` | サイトによってはダイアログが抑止される。マスク操作や検出内容の一覧を表示できず、F-04・F-05を満たせない |
| 拡張機能のポップアップ（action popup） | 利用者のクリックなしには開けず、送信操作に同期して表示できない |

## 結果

**得られるもの**

- サイトのCSS改修に影響されないUIと、ページから操作されない防御解除ボタン
- 検出値をDOMに残さない

**引き受けるもの**

- closed Shadow DOM内はDevToolsからも辿りにくく、UIの不具合調査がしづらい。開発ビルドでのみopenにするなどの手当てを検討する
- スタイルをShadow DOM内に閉じて持つ必要があり、外部CSSの再利用ができない
- フォーカストラップとキーボード操作は自前実装になる。アクセシビリティの検証項目としてテストに含める
