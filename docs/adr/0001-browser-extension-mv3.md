# ADR-0001: 対策の実装形態をChromium系ブラウザ拡張（Manifest V3）とする

- ステータス：採用
- 日付：2026-09-20
- 関連：開発ドキュメント 1.2, 2.3, 2.4

## コンテキスト

業務端末から生成AIチャット（ChatGPT、Claude、Gemini、Copilot、Perplexity）へ、健康保険の被保険者記号・番号などの個人情報が誤って入力されることを防ぎたい。要件の中心は次の3点である。

1. **送信前に止める**こと。送信後の検知・通報では情報はすでに外部へ渡っている
2. **なぜ止められたかをその場で示す**こと。利用者がマスクして送信し直せる導線が要る
3. 対策そのものが**新たな漏えい経路にならない**こと

対象の通信はすべてTLSであり、入力内容は送信直前までブラウザのDOM上にしか存在しない。

## 決定

Chrome / Edge（Chromium系、Manifest V3）のブラウザ拡張機能として実装する。対象AIサイトにコンテンツスクリプトを注入し、利用者の送信操作を捕捉して検査する。Firefox / Safari は本バージョンの対象外とする。

## 理由

- 送信直前の**平文**に触れられる唯一の現実的な位置がブラウザ内である。ネットワーク側ではTLSの内側を見るために復号が必要になる
- 入力欄と同じ文脈にいるため、検出箇所のハイライト・マスク・再入力といった**利用者への即時フィードバック**が実装できる
- Chrome / Edge はいずれもChromiumのため、**単一コードベース**で両対応できる
- エンタープライズポリシーで強制インストールでき（ADR-0012）、利用者による無効化を抑止できる

## 代替案

| 案 | 却下理由 |
| --- | --- |
| ネットワーク側のDLP / CASB でのブロック | TLS復号基盤が必要でコストと影響範囲が大きい。ブロック理由を入力画面に返せず、利用者が対処できない。ただし意図的な持ち出しへの対策としては**併用が前提**（ADR-0012） |
| ブラウザポリシーによるAIサイトのURLブロックのみ | 業務での生成AI利用そのものを止めてしまう。許可したサービス内での誤入力は防げない |
| 端末常駐エージェント（クリップボード・キー入力監視） | 全アプリのキー入力を監視することになり、プライバシー影響と誤作動リスクが過大。導入・維持コストも高い |
| AIサービス側の管理機能・API経由の利用に限定 | サービスごとに機能差があり、提供されない場合がある。Web版の利用を止められない |
| Firefox / Safari も同時対応 | WebExtensionsの差異（MV3対応状況、Safariの拡張機能配布）で検証コストが倍増する。組織の標準ブラウザをChrome / Edgeに寄せ、他ブラウザは資産管理ツールで実行制限する方が確実（8.2） |

## 結果

**得られるもの**

- 送信前ブロックと利用者への説明を1つの仕組みで実現できる
- ポリシー配布・設定固定というブラウザ標準の運用基盤に乗れる

**引き受けるもの**

- AIサービスの画面改修に追従し続ける保守が必要になる（ADR-0011）
- 拡張機能が無効な環境（別ブラウザ、スマホ、デスクトップアプリ、API直接利用）は原理的に守れない。この穴は技術ではなく**運用（利用可能ブラウザの限定、規程、教育）**で塞ぐ前提とする
- MV3のService Workerは常駐しないため、状態を持つ処理はコンテンツスクリプト側に置く設計になる

## 再評価のトリガー

- 組織の標準ブラウザにFirefox / Safariが加わったとき
- 生成AIの利用形態がWeb版中心からデスクトップアプリ／API中心に移ったとき
