# ADR-0012: 配布をエンタープライズポリシーによる強制インストールとする

- ステータス：採用
- 日付：2026-09-20
- 関連：開発ドキュメント 8.1, 8.2, 8.4、ADR-0001, ADR-0008

## コンテキスト

本拡張は利用者の利便性を下げる方向に働く（送信を止める、マスクを求める）。利用者が自分でインストールし、自分で無効化できる状態では、締め切り間際に無効化されて終わる。防止策として機能させるには、**利用者が外せないこと**が前提になる。

一方で、ADR-0002により拡張機能自身は通信しないため、更新の配布経路は拡張機能の外に用意する必要がある。また、拡張機能を強制インストールしても、別ブラウザ・シークレットモード・対象外AIサイトといった迂回路が残る。

## 決定

ブラウザのエンタープライズポリシーで強制インストールする。配布方式は**社内Webサーバーに置いたCRXと更新マニフェスト（update.xml）**を `ExtensionInstallForcelist` で配布する形を本番の推奨とする。

| ポリシー | 目的 |
| --- | --- |
| `ExtensionInstallForcelist` | 強制インストール・削除不可 |
| `3rdparty` 配下の拡張機能ポリシー | `schema.json` に沿った設定の固定（`lockSettings: true` 等） |
| `DeveloperToolsAvailability` | DevToolsからの干渉・無効化の抑止 |
| `IncognitoModeAvailability` | シークレットウィンドウでの回避防止 |
| `URLBlocklist` / `URLAllowlist` | 許可していないAIサービスへの迂回防止 |
| 資産管理ツールでの実行制限 | Firefox等、対象外ブラウザでの回避防止 |

開発者モードでの読み込みは**開発・検証のみ**とする。Google Workspace管理下であればChromeウェブストアの限定公開、Edge標準の組織であればEdgeアドオンも選択肢とする。

**拡張機能単体では防御が完結しないことを前提**に、規程・教育・ネットワーク側のDLP/CASBと組み合わせて運用する。

## 理由

- **強制インストールと設定固定**により、「利用者が外せない」「利用者が緩められない」というF-09の要件を、拡張機能側の作り込みではなくブラウザ標準の機能で満たせる
- **社内サーバー配布**は、ウェブストアの審査待ちに依存せず、組織のタイミングでリリースできる。セレクタ修正（ADR-0011）は緊急性が高いことがあるため、この独立性は実利がある。更新の取得はブラウザ本体が行うため、ADR-0002の通信ゼロと矛盾しない
- **迂回路を塞ぐポリシーをセットで定義**するのは、拡張機能だけを入れても実効性が出ないため。シークレットモードや別ブラウザが空いていれば、そちらが使われる
- **DLP/CASBとの併用**：本拡張は「うっかり入力」を止めるガードレールであり、意図的な持ち出し（画像化、分割入力、スマホ利用）は防げない。この境界を配布方針の段階で明示する（1.3, 8.4）

## 代替案

| 案 | 却下理由 |
| --- | --- |
| 利用者による任意インストール | 無効化・削除が自由なため、防止策として機能しない |
| Chromeウェブストアでの一般公開 | 審査に時間がかかり、セレクタ修正の緊急リリースができない。社外に組織固有のルールが出る懸念もある |
| ウェブストア限定公開のみ | Google Workspace管理下でなければ使えない。Edge環境との二重管理になる |
| ポリシーは強制インストールのみ（設定固定なし） | 利用者がルールをOFFにできてしまい、実質的に無効化と変わらない |
| 拡張機能側に無効化防止の独自機構を作る | ブラウザの機能で実現できることを自前実装するのは筋が悪く、保守と回避の追いかけっこになる |

## 結果

**得られるもの**

- 利用者が外せない・緩められない状態で配布でき、要件F-09を満たせる
- リリースのタイミングを組織側で制御できる

**引き受けるもの**

- CRXの署名鍵の管理、update.xml の更新、社内Webサーバーの維持という**配布基盤の運用**が発生する
- ポリシー名と値はブラウザのバージョンで変わるため、導入時とブラウザ更新時に公式のポリシー一覧での確認が必要になる（8.2）
- 強制インストールと設定固定は、誤検知が起きたときに利用者側で回避できないことを意味する。fail-closed（ADR-0006）と併せると、不具合が業務停止に直結する。**少人数での試験導入を経てから全社展開する**（8.5）
- ブラウザポリシーを配れない端末（BYOD等）は対象外となり、運用ルールでの対応が必要になる
