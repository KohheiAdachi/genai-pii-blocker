# ADR-0011: サイト依存部をアダプタに分離し、汎用セレクタでフォールバックする

- ステータス：採用
- 日付：2026-09-20
- 関連：開発ドキュメント 2.2, 2.3, 4.4, 5.5, 8.3

## コンテキスト

ADR-0003でUIイベント捕捉を主防御に据えた結果、**AIサービスの画面改修が最大の運用リスク**になった（8.3）。入力欄や送信ボタンのDOM構造は事前の告知なく変わり、変わった瞬間に検査が素通りする。しかも素通りは静かに起き、利用者は守られているつもりのまま個人情報を送信する。

対象は5サービスあり、それぞれ入力欄の実装（`textarea` / ProseMirror系 `contenteditable`）もボタン構造も異なる。さらに同一サイト内でも、新規入力欄と過去メッセージの編集欄でセレクタが違う。

## 決定

サイトごとのDOMセレクタを `src/sites.js`（`globalThis.PII_SITES`）にホスト名をキーとして分離し、検出ロジック・イベント捕捉ロジックから切り離す。

- **多段フォールバック**：`PII_SITES[location.hostname]` → 見つからなければ `PII_GENERIC`（汎用セレクタ）を使う
- 汎用セレクタは `textarea`、`[contenteditable="true"]`、`button[type=submit]`、`aria-label` に「送信」「Send」を含むボタンを候補とする
- 入力欄の探索は「イベントの `target` からの `closest()`」と「`document.querySelector`」の併用とし、**SPA遷移での再生成に `MutationObserver` で追従**する
- セレクタの妥当性は、対象サイトごと・リリースごとに手動チェックリスト（7.3）で確認する。月1回と、各サービスの大型アップデート告知時に実施する

## 理由

- セレクタは**壊れる前提**のデータであり、ロジックと混ぜるとサイト改修のたびにコード全体の回帰試験が必要になる。分離しておけば、修正は1ファイルの値の変更で済み、非機能要件2.2の「設定変更だけで追従できる」を満たす
- **汎用セレクタのフォールバック**は、サイト固有セレクタが外れたときに完全な素通りではなく「部分的にでも捕捉する」状態を作る。過去メッセージの編集欄のような、固有セレクタが用意されていないUIもここで拾える可能性がある
- サイト別セレクタと汎用セレクタの**両方を常に試す**ことで、片方が外れても即座に無防備にはならない
- 定期チェックを運用に組み込むのは、**壊れたことに気づく仕組み**が他にないため。通信ラッパ（ADR-0004）は既定OFFであり、自動検知には使えない

## 代替案

| 案 | 却下理由 |
| --- | --- |
| セレクタを `content.js` に直書きする | サイト改修のたびにロジックを触ることになり、回帰リスクと保守コストが上がる |
| 汎用セレクタのみ（サイト固有を持たない） | 送信ボタンの特定精度が落ち、誤捕捉（送信でないボタンでモーダルが出る）と捕捉漏れが増える |
| サイト固有セレクタのみ（フォールバックなし） | 改修で外れた瞬間に完全な素通りになる |
| セレクタをサーバーから配信して即時更新する | ADR-0002の通信ゼロに反する。緊急更新は管理者ポリシー経由で行う |
| ホスト名ではなくURLパターンでアダプタを選ぶ | 同一ホスト内でパスによる差異が現れたら検討する。現時点では過剰 |

## 結果

**得られるもの**

- サイト改修への対応が、1ファイルの値の変更とテスト実行で完結する
- 固有セレクタが外れても、汎用セレクタによる部分的な防御が残る

**引き受けるもの**

- **月次の実機チェックという継続的な運用コスト**を負う。これを止めた時点で、防御は静かに劣化する
- 汎用セレクタは誤捕捉を生みうる。検出がなければ素通りするため実害は小さいが、送信以外のボタンで検査が走る分の性能影響はある
- 新しいAIサービスを対象に加える際は、`manifest.json` の `matches` / `host_permissions` と `sites.js` の両方を更新し、拡張機能の再配布が必要になる
