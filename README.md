# pii-guard

生成AIチャットへ個人情報を**送信する直前**に端末内で検査し、見つかったら送信をいったん止めて確認を求めるChrome / Edge拡張機能（Manifest V3）。

健康保険の被保険者番号やマイナンバーなど、業務で「うっかり入力」しやすい番号を対象にしています。

**拡張機能自身は外部通信を一切行いません。** 検査・判定・ログはすべて端末内で完結します。対策そのものが新しい情報漏えい経路になっては本末転倒だからです。

```
入力 → [検査] → 検出あり → 確認ポップアップ →「マスクする」「編集に戻る」「このまま送信する」
                 検出なし → そのまま送信
```

## スクリーンショット

確認ポップアップには、**なぜ止めたか**（形式・チェックディジット・周辺のキーワード）が表示されます。検出した番号は伏せ字になり、完全な値は画面にもログにも残りません。

```
⚠ 個人情報が含まれている可能性があります
   送信しようとした内容に次の情報が見つかったため、いったん止めました。

   [警告] 保険者番号  06******
   判定理由: 8桁の数字という形式が一致 / 検証番号（チェックディジット）が一致
            / 近くに「保険者番号」というキーワードがある

   [該当箇所をマスクする] [編集に戻る] [このまま送信する]
```

「該当箇所をマスクする」を押すと、入力欄が `保険者番号 [保険者番号]` のように書き換わります。AIに渡したい文脈は残したまま、番号だけが消えます。

## 状態

**個人のPOC（概念実証）です。** 動きますが、検出できる種別は2つだけで、対応サイトも ChatGPT のみです。

| | |
| --- | --- |
| 対応サイト | ChatGPT（`chatgpt.com`） |
| 検出できる種別 | 保険者番号（8桁・国保6桁）、マイナンバー |
| 判定 | 警告のみ（送信を止めて確認を求める。ブロックはしない） |
| 動作確認 | 2026-10-04 時点の ChatGPT で確認（[記録](docs/roadmap.md#動作確認の記録)） |

残りの作業は [ロードマップ](docs/roadmap.md) にまとめてあります。

## 使い方

```sh
git clone https://github.com/KohheiAdachi/genai-pii-blocker.git
```

1. Chrome / Edge で `chrome://extensions` を開く
2. **デベロッパーモード**をONにする
3. **「パッケージ化されていない拡張機能を読み込む」**で、clone したディレクトリのルートを選ぶ
4. ChatGPT を開く

ビルドは不要です。素のJavaScriptをそのまま読み込みます。

### 試す

入力欄に次を入れて Enter を押すと、ポップアップが出ます。**以下はすべてダミー値で、実在の番号ではありません。**

```
保険者番号 06130017
マイナンバーは123456789018です
```

検証番号が合わない値（`保険者番号 06130018`）や、関連キーワードのない数字は検出されません。

> **実在の個人情報で試さないでください。** チェックディジットを満たすダミー番号の生成方法は [調査記録](docs/research/2026-09-21-kouhi-koukikoureisha-number-format.md) にあります。

## 何をどう検出しているか

「正規化 → パターン照合 → チェックディジット検証 → 文脈キーワードによるスコア加算 → 判定」の順で検査します。

**チェックディジットだけでは足りません。** 8桁の数字が保険者番号の検証を偶然通る確率は約10%あり、業務文書中の任意の数字列が一致します。**キーワードだけでも足りません。**「番号」は日常語です。両方をスコアとして合算し、「注文番号」「郵便番号」といった否定キーワードで減点します。

全角数字（`０６１３００１７`）や区切り付き（`0613-0017`）も正規化してから照合します。元テキストとの位置対応表を保持しているので、マスクは元の表記のまま正しく置換されます。「データーを整理」の長音をハイフンと誤認しないよう、ハイフン類の統一は数字に挟まれた場合だけに限定しています。

保険者番号・公費負担者番号・受給者番号の検証番号は、厚生労働省の「保険者番号等の設定要領」第1の5 に定められた計算で、これは **Luhn アルゴリズムと一致します**（[調査記録](docs/research/2026-09-21-kouhi-koukikoureisha-number-format.md)）。

## 設計上の約束

これは好みではなく、[ADR](docs/adr/) で決めた制約です。破ると、その決定が成立しなくなります。

### 外部通信をしない

`fetch` / `XMLHttpRequest` / `WebSocket` / `EventSource` / `navigator.sendBeacon` / `import()` を使いません。これを宣言ではなく4層で担保しています（[ADR-0002](docs/adr/0002-zero-network-standalone.md)）。

| 層 | 対策 |
| --- | --- |
| コード | 通信APIを使わない。同梱コードの依存ライブラリはゼロ |
| ビルド | `npm run check:no-network` が混入を検出し、CIで落とす |
| CSP | `connect-src 'none'` をブラウザに強制させる |
| 権限 | `permissions` は `storage` のみ。`webRequest` / `<all_urls>` / `tabs` / `identity` を要求しない |

### 検出した値を保存しない

入力テキストと検出値はメモリ上で検査したら破棄します。保存するのは「件数」と「設定」だけです。`console` への出力も禁止しています（DevToolsのログは他の拡張機能やページのスクリプトから読める場合があり、保存しない方針の抜け道になるため）。

`chrome.storage.sync` は使いません。書くだけで Google アカウント経由でクラウド同期されてしまいます（[ADR-0008](docs/adr/0008-storage-local-managed-only.md)）。

### 止めるのではなく気づかせる

ルールベースの検出では誤検知を避けられません。誤検知の代償が「送信できない」だと、利用者は別のブラウザやスマートフォンへ回避します。そこは完全に無防備です。

そこで**既定の判定はすべて警告**とし、送信前に止めて確認を求めるだけにしています。誤検知の代償は1クリックに収まり、止める地点は送信**前**のままなので防止策としての価値は落ちません（[ADR-0013](docs/adr/0013-warn-only-with-confirm-popup.md)）。

### 無効化されない位置に置く

検出ロジックは ISOLATED world で動かし、ページのスクリプトから書き換えられないようにしています。確認ポップアップは closed な Shadow DOM に描画し、「このまま送信する」ボタンは `event.isTrusted` を検証します。すべての検出にこのボタンが出る以上、これを押させれば全防御が外れるためです（[ADR-0003](docs/adr/0003-isolated-world-ui-capture.md) / [ADR-0009](docs/adr/0009-closed-shadow-dom-ui.md)）。

## これで防げないこと

**ガードレールであって、DLPではありません。** 「うっかり入力」を止める仕組みであり、意図的な持ち出しは防げません。

| 回避手段 | 状況 |
| --- | --- |
| 画像・スクリーンショット・PDF内の文字 | 検出できない |
| 番号を分割して複数回送信、漢数字や読み上げ表記 | 検出できない場合がある |
| 別のブラウザ、スマートフォン、デスクトップアプリ、API直接利用 | 対象外 |
| サイトの画面改修でセレクタが外れる | 一時的に捕捉漏れ。**自動検知する手段はない** |
| 利用者が警告を承認して送信 | 送信される（既定ではすべての種別が該当） |
| 氏名・住所・病名単独 | 番号ほど確実に判定できない |

最後の行が特に重要です。**セレクタが外れると、検査は静かに素通りします。** 利用者は守られているつもりのまま送信します。組織で使う場合は定期的な実機確認が前提になります（[ADR-0011](docs/adr/0011-site-adapter-separation.md)）。

組織で運用するなら、ネットワーク側のDLP / CASB、端末管理、利用規程と教育を組み合わせてください。この拡張機能だけでは完結しません。

## 開発

```sh
npm install
npm test               # 単体テスト（Vitest）
npm run check          # 通信ゼロチェック＋テスト
npm run check:no-network
```

`test/manual/modal-preview.html` をブラウザで直接開くと、確認ポップアップの各パターンを目視確認できます（ChatGPT不要）。

### 構成

```
manifest.json          Manifest V3
src/rules.js           検出ルール（JSONではなくJSとして同梱。ADR-0007）
src/detector.js        検出エンジン
src/sites.js           サイト別セレクタ＋汎用フォールバック
src/modal.js           確認ポップアップ（closed Shadow DOM）
src/content.js         イベント捕捉と送信制御
scripts/               ビルド時チェック
test/                  単体テスト
docs/                  設計ドキュメント
```

バンドラ・トランスパイラは使いません。MV3 は `manifest.json` に列挙した素のJSをそのまま読み込みます。検出ルールをJSONではなくJSモジュールとして同梱しているのも、読み込みに通信APIを要さないようにするためです（[ADR-0007](docs/adr/0007-rules-as-js-not-json.md)）。

Vitest のような**開発用 devDependency は「依存ゼロ」の対象外**です（同梱コードの話）。ただし数は最小限に保ちます。
